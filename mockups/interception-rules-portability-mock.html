MOCKUP — not the running app. Export, duplicate and re-import interception rules.

Rules you can copy, keep and hand to somebody else

A rule is a piece of work — a match, a condition tree, a set of actions. Right now it exists only inside one deployment's database, and the only way to move it is to rebuild it by hand.

1 · The rules list — two new controls per row, one in the header

⧉ Duplicate and ⤓ Export are icon buttons, sitting with the ▲▼ icons the row already has, so the two worded buttons stay Edit and Delete. The header gains Export all and Import.

A copy arrives switched OFF, and the editor opens on it. Nobody duplicates a rule to keep two identical ones — you duplicate to change something. And a copy of a rule that delays live traffic, or holds a caller, that started applying the instant you clicked would double that effect with no warning. It lands next to its original (same priority), named … (copy), then (copy 2).

2 · The file

alfred-interception-rules-2026-09-20T164055.json — no ids, no timestamps. Those are assigned by whichever Alfred the rules land in, and carrying one would raise "does importing overwrite the rule with that id?", a question with two bad answers. Rules always import as new rules.

alfredInterceptionRules: 1 is the version and the fingerprint: a calls export is also a .json, and feeding one to the wrong importer has to say so rather than half-work. The master switch is not in the file — that is a property of a deployment, not of a rule, and no file should be able to turn interception on.

3 · Import — read it before it runs

No merge-by-id or overwrite. Import always creates. Matching on a name would silently replace a rule somebody spent an afternoon on; matching on an id would make the file carry the identity of a database it came from. If you want a rule replaced, import it and delete the old one — two visible steps beat one invisible one.

Import never touches the master switch, and never reorders your existing rules. Imported rules go to the bottom, keeping their relative order from the file.
