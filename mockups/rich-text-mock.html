Rich text on the board - mock

Every long text on the board - comments, replies, answers, descriptions, the cycle brief, spec files, checklist evidence - gets a visual editor with a toolbar, and the board shows it with colour, callouts, tables, checklists, collapsible evidence and pictures. It is stored as HTML - cleaned on save to a safe set of tags - with mentions kept as @[call:…|…] inside it, so the re-indexing of mentions, Claude's Did / Found / Next, exports, search and every MCP tool keep working. Global variables of the active environment show their value. Click around: the editor below works.

3. The rules

Kept on save (the backend cleans every write - the user's and Claude's)
p h1-h4 br hr b strong i em u s mark sub sup kbd code pre blockquote ul ol li table thead tbody tr th td a img details summary aside span div
Attributes: href (http/https/mailto), src (Alfred's own pictures), dir, colspan/rowspan, data-callout (info/warn/bug/ok), data-checklist / data-checked, data-color (red/green/amber/blue - theme colours, no free CSS)
Pictures: pasted / dropped screenshots, stored in Alfred with the card (/board/images/…), up to 5 MB each, exported with the board
Never
No innerHTML: the HTML is parsed into a typed tree and drawn with bindings - twice safe: cleaned on save, allow-listed again on show
No scripts, style, class, on…= handlers, iframes, forms, SVG, or outside pictures
No rewrite of old text: Markdown written so far shows as it does now, and becomes HTML only when someone edits it
Exports keep the text untruncated: .json the HTML as stored, .md converted to Markdown, secret variables redacted

4. What does not change

  • Mentions - @ picker, chips, "pick from anywhere", re-index on save, live calls kept from the limits, board_evidence.
  • Claude's comment rules - Did / Found / Next, Reply, Question still recognised (the parts now hold rich text).
  • Claude reads and writes through the same MCP tools: it reads the HTML turned into compact Markdown (fewer tokens), and writes Markdown or the allowed HTML - the backend stores HTML either way.
  • Enter sends in comments / replies, Ctrl+Enter in descriptions and briefs; ⇄ text direction per block; Ctrl+Shift+X.
  • Spec files - checklist items (- [ ]) are still the acceptance items; section anchors for spec mentions still work.
  • Search, similar cards, closed reasons, "same problem" refusals read the plain words (tags stripped).
