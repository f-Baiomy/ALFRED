Conditional rules

A rule stops being "always do this" and becomes "look at the call, then decide".

1 · The conditional card, in the request lane

A condition group is a step in the pipeline, sitting in the same list as the actions and dragged the same way — not a second mechanism bolted on beside them. Branches are tried in order; the first one that matches wins, and nothing below it runs.

2 · Operators

The same set everywhere, so a condition reads the same whichever half it looks at. A subject that is absent is never equal to, contains, or matches anything — so does not equal on a missing header is true, and exists / does not exist are there to say it outright rather than leave you inferring it.

exists

Present at all, whatever the value — including empty.

does not exist

The header / field / parameter is not there.

equals / does not equal

Whole value. Case-insensitive by default, with a toggle.

contains / does not contain

Substring, on a header value or a whole body.

matches regex

Compiled once when the rule loads, never per call.

is at least / is at most

Numeric — for a status, or a JSON number.

3 · What the call log shows afterwards

A rule that can take three different paths is only useful if the log says which one it took. The branch that ran is recorded with the condition that chose it — so "why did this call get a 401" is answered on the card, not by re-reading the rule and guessing.

4 · What I am NOT proposing

No nesting beyond one level in the first cut. A condition inside a branch is allowed in the model and the engine, and the + Condition button above is real — but the editor will refuse to go deeper than two levels, because a rule you cannot read at a glance is a rule that changes production-shaped traffic in a way nobody can predict.

No expression language. Subject / operator / value stays a form. The moment it becomes req.headers['x'] ~= /y/ && ... it needs a parser, an error surface, and a manual — and the whole point of this feature is that simulating a broken supplier should not require writing code into a proxy addon.
