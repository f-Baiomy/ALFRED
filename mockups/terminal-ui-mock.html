New: alfred in a terminal opens a live control panel

    
Typing alfred with nothing after it, in a real terminal, opens a full-screen panel: processes, Java apps and their agent, storage against its caps, traffic in the last minute, the latest calls, and one-key actions.
      The simulated key press here is r (restart): it asks first, then the rows change state in place.
      Piped, or with alfred help, you get the command list as before.

Alfred — Command Prompt

    

    
    
      
  • Data it reads, all existing: supervisor /status and /agents; backend /database/stats (storage), /triage/counts (attention), and the latest page of outbound and inbound calls.
    • 
      
  • No polling: it refreshes when the backend's WebSocket (/ws/, the same signal the web UI uses) says something changed. "Last 60 s" counts the calls that arrive while the panel is open.
    • 
      
  • Keys: s stop/start · r restart · p proxies · l logs (follow, Esc back) · t triage list · a attach (picks from the Java apps) · u update (with pause/cancel) · d doctor · o open the UI · q quit. Anything that stops Alfred asks first.
    • 
      
  • It adapts to the window: below 100 columns the two columns stack; below 24 rows "latest calls" shrinks first.
    •

alfred update: Ctrl+C gives a choice — pause or cancel

    
While downloading or checking, Ctrl+C stops the download and asks.
      Pause keeps the pieces already downloaded; the next alfred update (or the Settings card) continues from there, if the release is still the same one.
      Cancel deletes them, so the next update starts from 0.
      Once the installer runs, it can't be stopped: Alfred is mid-replacement.
      Today Ctrl+C only stops the waiting; the update carries on and there's no way to stop it.

    

      
After — Pause, then continue later
Administrator: Command Prompt

      
After — Cancel, start over next time
Administrator: Command Prompt

    

    
    
      
  • Supervisor: new POST /update/pause and POST /update/cancel; a new state PAUSED next to DOWNLOADING/VERIFYING/INSTALLING/FAILED.
    • 
      
  • A paused download keeps its .part file plus a small list of finished pieces (.part.json: version, sha256, size, pieces done), so a resume fetches only the missing pieces. A different release, or a missing or changed list, means starting over. Nothing is trusted without the final sha256 check.
    • 
      
  • Restarting Alfred keeps a paused download paused (it's on disk). alfred update --cancel discards a paused one without starting anything.
    • 
      
  • The Settings → Server card gets the same two buttons, so the terminal and the UI agree.
    • 
    

  


  

    
Update failures, the download cache, and choosing a version

    
Left: 3.0.6 installs but can't start because port 3000 is taken by another program. Alfred names the program, puts 3.0.5 back (nothing lost), and offers retry, another port, or keep 3.0.5. The retry installs from the cache, with no download.
      Right: 3.0.6 was paused, and meanwhile 3.0.7 and 3.1.0 came out. alfred update lists them; picking the newest jumps straight there and drops the paused 3.0.6 download.

    

      
After — the new version can't start
Administrator: Command Prompt

      
After — newer releases than the paused one
Administrator: Command Prompt

    

    
    
      
  • Put back on a failed start: both installers already restore the previous files when copying fails. New: the update keeps the previous version aside until the new one answers, so a version that installs but can't start is also undone.
    • 
      
  • Why it failed, in words: the port's owner (process name, pid, its command line) comes from the OS, the same way doctor finds it.
    • 
      
  • Download cache: finished and paused installers stay in data\updates (in-app update), and in C:\ProgramData\Alfred\downloads or /var/cache/alfred for the one-liners (not %TEMP%, which Windows clears). Every use checks sha256 again. The newest two releases are kept; alfred update --clear-cache empties it. doctor shows its size.
    • 
      
  • Versions to choose from: latest.json gains a short list of recent releases (version, date, one-line notes, url, sha256), written by the release workflow. Older installers stay on GitHub, so any listed version can be installed: alfred update --version 3.0.7.
    • 
      
  • Skip: s hides the skipped releases from status, the panel and the Settings card until something newer than them is out.
    •

Fallbacks: old console, piped output, NO_COLOR

    
The classic Windows console (conhost with Consolas) lacks the braille spinner and several symbols, so it gets an ASCII set; Windows Terminal, VS Code and Linux terminals get Unicode.
      When output isn't a terminal (the installers capture alfred _wait-health; CI; | tee), there's no colour and no redraw: one line per finished step, the same words.

Rules the implementation follows

    

      
Never colour aloneEvery state is a symbol plus a word (✓ done, ✗ failed, ● running, ○ waiting), so it reads the same without colour.

      
Plain when not a terminalNo ANSI codes and no \r redraws when stdout isn't a TTY, when NO_COLOR is set, or when TERM=dumb. Same words, one line per step.

      
Glyphs by terminalUnicode in Windows Terminal (WT_SESSION), VS Code and UTF-8 terminals; an ASCII set (| / - \, [x], # bar, +--+ box) elsewhere.

      
No new dependencyA small term.py next to alfred.py (bundled Python, standard library only). The install scripts carry their own few helpers.

      
Windows VT modealfred turns on virtual-terminal processing via SetConsoleMode. PowerShell 5.1 uses Write-Host -ForegroundColor, which works in every console.

      
Ctrl+C is cleanA spinner or bar restores the cursor and line. update says the install keeps running; logs -f just stops.

      
Words unchanged where tests or people rely on themRefusal texts ("needs an Administrator prompt") and exit codes stay as they are. The installers' captured lines stay one line each.

      
Live progress only while something runsstart/restart/update ask the local supervisor every 0.3 s until done or the existing 60 s limit. Nothing polls in the background.
