HTML snippets on the board - what they are, how they work, what each part does

A guide to the proposal, with a working demo in the middle. Read top to bottom: 1 the idea, 2 how it is built, 3 one story from start to end, 4 the demo, 5 every feature explained, 6 safety, 7 questions.

1 · The idea in one minute

Today

Claude can only write text on a card: Markdown, tables, code. When it wants to explain "where do the 2.4 seconds go" it writes a table of numbers and you build the picture in your head.

The board has a fixed list of things it can draw. Anything outside that list - a chart, a slider, a small dashboard - is impossible.

With HTML snippets

Claude (or you) can put a small web page inside a comment, a description, a brief, or as its own tab on the card. It is real HTML, CSS and JavaScript, so it can be anything: a chart, an interactive table, a what-if calculator, a diagram, a game.

It runs in a locked box inside the card. It can draw anything inside the box, but it cannot touch Alfred, your account, or the internet - unless it asks, and for anything that changes something, you click to allow it.

2 · How it is built - three layers

Why three layers: Claude writes snippets from recorded traffic, and recorded traffic can contain text someone else planted. If a snippet ran as part of Alfred's page it could act as you - delete cards, give the ✅ Go, change interception rules. Keeping it in its own box and letting it talk only through the bridge gives it full freedom to show, and gives you the final word on anything it wants to do.

3 · One story from start to end

1
You ask on card #33: "show me how the fix changed fare confirmation".
2
Claude writes a page called "Fare dashboard": HTML for the layout, ECharts (shipped with Alfred) for the chart, and one line saying which data it needs: calls to POST /fare-confirm since the fix.
3
The board opens it as a tab on the card, in the locked box. The bridge checks the data request is on the read-only list, fetches the calls from Alfred and hands them in.
4
Claude checks its work: the board takes a picture (PNG) of what the page drew and any errors from its console. Claude looks, sees two labels overlap, fixes it (version 4), and only then tells you it is ready.
5
It stays current: every time a new call to fare-confirm is logged, Alfred's WebSocket says "calls changed", the bridge sends the new list in, and the chart redraws. No refresh, no polling.
6
You act from it: you click "Post result as reply". The page asks the bridge; the board shows you the exact reply text; you click Do it; the reply is posted as you. You type a note in the page - it is saved with the card and everyone sees it.
7
Later: you open ⟲ Versions to see what Claude changed between v3 and v4, ⧉ Pop out the dashboard to your second screen, or ⬇ export the card - the .html export carries the same locked page.

5 · Every feature explained

Each card says: what it is · example of when it helps · how it works · who decides · the code a snippet writes.

What a snippet can DO

1Actions with consent

What: a button inside a snippet can ask the board to do something real: post a reply, answer Claude's question, run a skill, start a re-test, move or flag a card, create an interception rule, open a call.

Example: a re-test page shows 9/9 calls under target and offers "Propose Verified" - one click, you see the proposal, you confirm.

How: snippet → alfred.action(...) → board shows a dialog with the exact change → you click Do it or Don't → the snippet is told the result.

Who decides: you, every single time. A snippet cannot skip the dialog, and Claude's limits on the board still apply.

await alfred.action("reply", { text: "Re-test: 9/9 under 1 s" });
2Full read bridge + live

What: a snippet can read Alfred's real data: calls, request/response bodies, SQL statements and their rows, log lines, Redis commands, cycles, cards, rules.

Example: a dashboard that always shows the latest calls to an endpoint, instead of numbers Claude copied once and that go stale.

How: the snippet declares what it needs; the bridge checks it is on the read-only list, fetches it, masks secrets exactly as the board does, and sends it in. When Alfred's WebSocket says the data changed, it sends it again.

Who decides: the allowlist - read only, nothing that changes data. No question asked, like opening the card.

<script type="alfred/data" name="calls" src="calls?endpoint=POST /fare-confirm&since=fix" live></script>
alfred.on("calls", calls => draw(calls));
3Saved state

What: a snippet can keep its own small data with the card: a note, ticked boxes, a chosen option, a scenario's numbers.

Example: a re-test checklist page where you tick each step; tomorrow, and for your teammate, the ticks are still there.

How: alfred.state.set sends it to the board, which stores it with the card in Alfred (not in the browser), with a history.

Who decides: anyone who can edit the board. It is the snippet's own data - it never changes the card itself.

alfred.state.set("note", text);   const note = await alfred.state.get("note");
4Ask Claude from a snippet

What: a button in the snippet sends a question, with data attached, to the cycle's Claude chat.

Example: in a chart of call times you click the one slow bar → "Why is this call 1080 ms?" goes to Claude with that call attached.

How: same road as the ▶ run buttons: the question goes to the chat that owns the cycle; Claude's answer comes back into the snippet (and as a reply on the card).

Who decides: you confirm the first question a snippet sends; after that it can ask freely (you can switch that off).

const answer = await alfred.ask("Why is this call slower?", { calls: [id] });

What snippets are built WITH

5Library shelf, hosted by Alfred

What: well-known libraries ship inside Alfred, so a snippet can use them with no internet.

Chart.js chartsECharts rich chartsD3 any visual Plotly scientificMermaid diagramsThree.js 3D Preact + htm componentsAlpine.js small interactionsTailwind styling Marked Markdownhighlight.js code coloursPapaParse CSV dayjs dateslodash helpers

How: served from /board/lib/<name>/<version>/, pinned versions, included in the Docker image and the native installers. Big ones (Plotly, Mermaid, Pyodide) load only when a snippet uses them, so the board stays fast.

<script src="/board/lib/echarts/5.5/echarts.min.js"></script>
6Multi-file snippets

What: one snippet can be several files: the page, a stylesheet, script modules, and data files (JSON/CSV).

Example: a page that loads calls.json Claude attached, plus a shared chart.js module from the widget library.

How: stored together as one snippet; files are served to the box from memory, never from the internet.

--- index.html  ...  --- style.css  ...  --- chart.js  ...  --- calls.json
7Python in the browser

What: a snippet can run Python (Pyodide: pandas, numpy, matplotlib) inside the same locked box.

Example: Claude groups 300 calls by endpoint in pandas and draws a percentile chart with matplotlib, right in the card.

How: a ```python live block; alfred.calls() arrives as a DataFrame; a figure shows in place. About 15 MB, loaded the first time a Python snippet opens, then cached.

df = alfred.calls()
df.groupby("endpoint")["ms"].quantile(.95).plot.barh()
8Snippet errors visible

What: a small console under each snippet shows its JavaScript errors and console.log lines.

Example: a chart is empty - the console says "echarts is not defined (line 3)"; Claude reads it and fixes the script tag.

How: the box reports errors through the bridge; Claude reads them with an MCP tool. Hidden when there is nothing to show.

Where snippets live, and how Claude checks them

9Pages

What: full HTML apps attached to a card, a cycle or the project, shown as tabs ("Fare dashboard", "Re-test plan").

Example: a cycle has a "Flow dashboard" page with every step of the booking flow and its latest status; Claude updates it after each run.

How: a page is a snippet with a name and a place; Claude creates and edits pages with new MCP tools; you can too (＋ page).

10Pop-out window

What: open a snippet or page in its own browser window.

Example: keep the live dashboard on a second screen while you click through the app.

How: the new window holds the same locked box and the same bridge, so it stays live. Closing the card does not close it.

11Claude sees what it drew

What: after a snippet draws, the board takes a picture of it; Claude can look at the picture and at the console.

Example: Claude's chart labels overlap; it sees that in the picture, fixes the layout, and only then says "ready".

How: PNG saved with the snippet version (like a pasted picture); Claude opens it with an MCP tool (board_snippet_view).

12Versions & diff

What: every save of a snippet or page is kept. Compare any two: the source side by side with changes coloured, or the two pages drawn side by side.

Example: the dashboard looks different today - ⟲ shows Claude changed the grid margin in v4; restore v3 if you liked it better.

6 · Safety - what the locked box guarantees

A snippet canA snippet can neverWhy
Draw anything inside its boxChange the board page around itIt runs as a separate page (sandbox without same-origin)
Read Alfred data it declared, read-onlyCall Alfred's API itself, see cookies, read secrets unmaskedOnly the bridge talks to Alfred, through an allowlist
Ask to do thingsDo anything without your clickEvery action goes through the consent dialog
Use Alfred's librariesReach the internet (CDNs, APIs, images)Your choice: no network (CSP blocks every outside address)
Keep its own notes with the cardEdit the card, its comments or other snippetsSaved state is a separate store

A test in Alfred checks these locks on every build, so a later change cannot quietly loosen them.

7 · Questions you might have

Does Claude still write normal comments? Yes. Text, tables and the fixed blocks stay the default; a snippet is for when a picture explains better.

Can I write snippets? Yes - ◈ HTML in the toolbar or /html opens a code editor with a live preview next to it.

Arabic? The box starts with the comment's direction and the board's colours; Claude sets dir per part like any web page.

Exports? .html export embeds the same locked box (still works offline); .md keeps the source and a PNG; .json keeps it exactly.

Speed? Snippets off screen are paused; big libraries load only when used; a snippet is limited to 256 KB of source.

Does Claude see snippets when it reads a card? Yes - the source as written, plus the latest PNG and console errors when it asks.
