Relive exports - redesign

Same sample data in every view: cycle "Booking", run of Oct 2, 6:33 PM (B) vs Oct 2, 3:49 PM (A).

What changes, for every format

  • Opens with an answer, then "About this document" - one verdict line, then plain-language prose generated from the run: what Relive is, what this run did, what failed and why, how to read the rest. The same text in .html, .md and .json (about is the first key), like the main call exports' About This Document.
  • Cycle name, not its id (today the title is a UUID), real dates, duration, driver, who/what each step called (method + URL), LIVE / REPLAY, and outcomes in words (failed, not FAILED/COMPLETED_WITH_DIFFERENCES).
  • Needs attention first: failed steps and steps with differences, each with its reason in one sentence, linked to the step.
  • Every step is one card: facts (mode, status recorded → this run, time recorded → this run, rules, variables), why it failed, the differences as a table (field | recorded | this run | noise or not), then request sent, response received and the recorded response - pretty-printed, full, never truncated (hard rule), folded in .html / .md so the page stays readable.
  • Children under their parent (an inbound step and the supplier calls it made), numbered 1, 1.1, 1.2, 2…
  • Values captured and the run log at the end, then a short glossary (LIVE, REPLAY, noise, attribution…) so a reader outside ALFRED - or an AI agent - can follow every term.
  • .html: self-contained, slate palette of the other exports, sticky contents on the left with each step's colour, filter chips (All / Failed / Differences), copy buttons on bodies, prints cleanly. .md: GitHub-flavoured, tables + <details> folds, renders well on GitHub / in an editor / in a chat with an agent. .json: format + about first, readable field names, both nested by step - secrets left unmasked as today (it is the data format; .html and .md mask them).
  • The comparison report gets the same treatment, with A (blue) and B (violet) side by side, and the run report from the History column menu, the run view and the comparison use one builder each.
