Relive steps shown with the Live Calls call card

Inline only - the side drawer goes away. Every step, in the Steps tab and in a run, opens the same call card Live Calls uses: badges, URL, Resend / Pin / Export / Relive, REQ/RES headers and bodies, the ⚡ intercepted panel, the error banner. What Relive adds is one more panel in the card's existing panel family (the twin of "Intercepted" and "Resent from a Live Calls call"): the same head, the same numbered strip, the same Request / Response diff. Click the strip boxes and the panel heads.

What is reused, unchanged

  • app-call-card (through app-relive-step-call, already used today) - the whole card, its actions, its REQ/RES panels and its error banner. A step that hasn't run shows its recording; a step of a run shows the call the run actually made.
  • app-interception-panel - the ⚡ "Intercepted" panel for rules that changed the call during the run (exactly as for a Live Calls call), and in embedded mode for the Request / Response diff inside the Relive panel.
  • app-call-step-strip - the numbered strip. The run timeline already uses it; the Steps tab starts using it too.
  • app-resend-panel's frame - the new app-relive-panel copies its structure (head → strip → step detail → Request/Response halves). Better still, the shared part becomes one base both use, so the two can't drift.
  • app-resend-call-editor (the Resend dialog's editor) for "Your edits", app-body-editor/app-header-editor for ALFRED's answer, app-rule-action-card + the rule dialog for the call rule, app-json-path-input and app-scenario-assertion-editor for values.

The step's call configuration (box 5 · Call rule)

  • It is the Interception page's rule editor (app-rule-editor) embedded in the card, with the Relive target it already has: the same pipeline (1 Request → host → 2 Response), the same action cards, drag to reorder, enable switches, "＋ Add action", "Browse body…".
  • The match is fixed by the step (only this step's call), so the editor's Match section is replaced by one line. "Open in full rule editor" opens today's rule dialog for anything bigger.
  • Mode, pauses, your edits and ALFRED's answer are actions in this one rule - boxes 2, 3 and 6 are shortcuts that edit them, and each card says which ("your edit", "REPLAY", "checkpoint"). That is how it already works today; the mock just shows it in one place.
  • The host box shows whether the call reaches the host: LIVE goes to your app or the supplier; REPLAY is "Not sent" and lane 2 greys out, using the rule editor's existing "host is never contacted" logic.
  • Relive-only settings sit under the pipeline: "If ALFRED can't tell the call is yours" (REPLAY children), which cycle and global rules also apply, and Reset call rule. "When the request differs" is an action card in lane 1, as it is in the rule today.
  • Open the Supplier B price child step in the mock to see a REPLAY call's rule.

Extract & assert (box 7 · Values)

  • Save a value uses the look of the rule editor's "Capture a value" action card (source JSON field / header / cookie, path, name, if-missing), and its app-capture-value-preview - but the preview runs on this step's own recording, so there is no "pick a call". It also says which later steps use the value.
  • Browse response body is the rule editor's app-json-browse on the recording: click a field to save it or to add a check on it. Noise fields are marked.
  • Check the response is app-scenario-assertion-editor unchanged (STATUS / JSON / HEADER / LATENCY × the same operators), plus a "passes on the recording" result per check so a wrong check shows before running.
  • The data is unchanged: still the step's extract and assertions, not rule actions.
  • In a run, box 8 shows each saved value (this run vs recorded, and what it unblocked or blocked) and each check's expected / got / result - replacing the drawer's "Variables produced" and the assertion lines.

Kept Relive-only

  • Ignore-field / count-field actions on differences, the noise list, and "Run from here" - they live in the Response box and the step row, not in the shared card.
  • Held-call decisions (Continue / Replay / Send real) stay on the run timeline's pause banner.
