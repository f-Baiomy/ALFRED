Compare two runs - redesign

Pick any two runs (A = before, B = after) from History - or one run and "Compare with the previous run" / "with the recording". The comparison opens as a page of its own: a summary of what changed, a step-by-step table that defaults to changed steps only, and each step expandable to its field changes, request changes, timing and variables. Noise rules apply by default. Click around: the A/B slots, the stat tiles, the filters and the rows.

Option C - both together

  • The History tab becomes the matrix: the runs are its columns (with their own Open / Export / Compare with recording / Delete on the column head), steps are its rows.
  • The two runs you pick - A by clicking a column head, B by shift-clicking (or the last two runs by default) - are compared directly under the grid with option A's page: verdict line, tiles, changed steps, expandable fields / what was sent / values, export.
  • Clicking a cell selects that run pair and opens that step's row in the comparison below, scrolled into view.
  • So one screen answers both questions: since when? (the grid) and what exactly changed? (the comparison).

Option B - run matrix (in short)

  • One grid: steps down, the last runs across (newest left), each cell the step's outcome (✓ ≠ ✗ –) or its time against that step's usual time (faster / usual / slower / much slower).
  • Answers "since when?" at a glance: a row that was ✓ ✓ ✓ ✓ ✓ and is ✗ in the newest run started failing between those two runs; a row that flips ≠ / ✓ is a flaky answer or an unignored noise field.
  • "What stands out" column names it in words (first failure in N runs, twice as slow, flaky).
  • Click a column head for A, shift-click for B; click a cell to diff THAT step between A and B underneath (fields that changed, both answers). "Open the full comparison" leads to option A's page for the whole run.
  • Better for trends and many runs; option A is better for one careful before / after.

Option A - what changes from today's "Compare with newest"

  • Any two runs, not just "this one vs the newest": click A then B in the history list, or use a row's Compare with ▾ - the previous run, the newest, or the recording (what each step's own differences already compare against, now for the whole run in one view).
  • An answer first: verdict line ("B is worse: 1 new failure, 1 slower step") and tiles - new failures, fixed, changed answers, slower, faster, same. Clicking a tile filters the table to it.
  • Step table with outcome, status, time and fields side by side as ✓ → ✗, with a time bar (A blue, B purple) and the change in %. Children sit under their parent step.
  • Changed steps only by default; "All steps", a search, and the step's own name / path.
  • Noise rules applied (cycle + step + auto noise), so a timestamp or a session id does not make every step "changed"; "Show noise" brings those fields back, greyed, and each field has "Ignore in cycle" to add a noise rule from here.
  • Expanded step: the response fields that changed (A value | B value), what the step sent differently (variables, edited body), status and timing, rules applied in each run, and "Open in run A / B" to jump to the step in that run's timeline.
  • Variables section: every value each run captured, side by side - often the reason a later step differs.
  • Export the comparison (Markdown / HTML / JSON), like a run.

Reused

  • The field diff and noise handling of the run's own differences (relive-canonical-body, noise rules), the run's own step results and variable timeline - no new backend data, both runs are loaded with getRun.
  • The Request / Response halves of a step open the existing app-interception-panel diff (A vs B), as in the result panel.
