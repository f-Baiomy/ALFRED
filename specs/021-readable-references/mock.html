What gets built

  • No new chip, no new popup. Every reference is one of the existing mention types (call, stmt, log, redis, spec, card, cycle, rule, code) with its meaning as the label; it opens the popup that type opens today.
  • Small additions to existing popups (marked new): the call popup opens at the statement / log line / Redis command a stmt/log/redis chip points at; the spec viewer shows an acceptance item's verdict and its calls (each a call chip); the drawer scrolls to a comment a chip points at.
  • Plain words for what has no page: verdicts (NO_DATA), check names (REQUEST_WHEN), app starts, listen batches, run ids - written out, with a hover tip.
  • Rule (rules.md, MCP tool descriptions): never a bare code; history indexes never appear in text you read.
  • MCP on every write: each shorthand is looked up and saved as its mention; [i] → who and when; an unknown code is reported back to Claude.
  • Short names: optional per acceptance item and per card - Claude proposes, you edit; derived when missing.
  • Old cards: readable at once on display; optionally rewritten once.
