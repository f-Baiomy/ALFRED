4 · How a line is matched - and where you set it up

a) Exact - the agent tags the log. The db-agent already knows each call (the X-Alfred-Call header). It also puts the call id in the logging MDC (alfred.call) for the time the request runs - WildFly/JBoss Logging, SLF4J/Logback and Log4j2 all read it - so a JSON log that writes the MDC carries "mdc": {"alfred.call": "500d0cdc-…"} on every line of that call, even from other classes. No guessing. Only odeysys's log format has to include the MDC (WildFly's JSON formatter does by default). exact

b) Same thread + time - for logs already written. A WildFly request runs on one thread (default task-4, which the agent records with every statement): lines of that thread between the call's start and end belong to it. Works on today's files with no change; a call that hands work to another thread (async) loses those lines, and the log and Alfred clocks must agree (an allowed skew, default 200 ms). same thread + time

c) Shared value (optional): a field the app logs that also appears in the call - a booking reference, a session id. mentions BKG-4411
