Build steps (after you say start)
  1. Backend: a bundle made for a card gets that card's board; GET /teamboards/writes?board= then finds it. Old bundles get theirs on start.
  2. Backend: state and field steps carry the current Azure value (from), read when the bundle is made and refreshed on open.
  3. Frontend: one review component (old → new, edits vs draft, tick, edit, approve) used by the tray, the chat answer and the card strip.
  4. Header pill + tray; tile badge; card drawer strip above the tabs; "wait on you" counts bundles. Live through the /ws/teamboards signal, no polling.
  5. Chat: a Claude answer that made a bundle shows it inline (the chat record names the bundle id).
  6. Skills: a change the user asked for always goes in the bundle; one Azure may refuse is warned in it.
