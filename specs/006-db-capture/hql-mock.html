Three cases, one rule - what your code wrote on top, what the database received below, and a line saying what changed in between:
· HQL → translated to SQL (always different).
· NATIVE SQL through Hibernate → usually the same text with :name parameters turned into ?; when Hibernate changed more (paging, {alias.*} expansion, a lock hint) the line says so and the SQL card is marked "differs from the code". When nothing changed but the parameters, the two cards collapse into one.
· JDBC (or Spring JdbcTemplate, MyBatis…) → written as SQL and sent as written: one card. The row shows the SQL either way, so "Show rows as HQL" only changes HQL rows.

How the agent gets it. Today it only sees JDBC. It would also watch Hibernate's query execution (Hibernate 5 - what WildFly 16 ships - and 6: Query.list / getResultList / uniqueResult / executeUpdate / scroll, named and native queries, Criteria), keep the query text, its name and its named parameters on the thread while the query runs, and tag every SQL statement executed inside with it. Lazy loads, entity loads and flushes are recognised from Hibernate's own events. Nothing changes for apps without Hibernate - the HQL parts simply don't appear. Same Java 8 agent; same "recording only" rule.
