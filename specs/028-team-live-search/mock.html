SkillWhat changes
_shared/rules.md
all skills
  • Token: Alfred holds it in memory; Claude never sees or asks for it. A team_* read with no live token: tell the user "enter your token in the Team tab", never guess from old data.
  • Work items are read live (team_search, team_item, team_tree, team_items_live); the old cache tools (team_items, team_changes, team_squads) are gone.
  • Full copy vs reference: the board's ★ main and card-linked items have saved copies and diffs; every other item is a reference - read it live, quote nothing from memory.
  • Every Azure write (comment, state, create, link, tag, attachment) is a proposal in one consent card; say what is in it and that it waits for the user. Never write bodies, headers, SQL values or log lines into Azure; exports go redacted.
  • Person mentions @[person:azure/|Name]; "me" is the person Alfred reports (team_people), never a guess from a name.
  • Azure arrivals are proposals too: team_propose_card (New card or Link to #n, with a reason); nothing is created or linked until the user accepts.
/alfred-setup
start a task
  • From "AB#4521", a Team search row (Start board) or a pasted Azure URL: team_item live, then team_tree of it.
  • The started item becomes the ★ main; the brief and Acceptance items are seeded from it (description, acceptance criteria, children as steps).
  • Links the main with team_board_link (askedIn); its tree stays as references. Offers watch rules ("new bugs under this item", "bugs in this area") as a proposal.
  • The first cycle is recorded for this board; the cycle page shows calls only.
/alfred-triage
sort the Inbox
  • Sorts the Incoming from Azure lane first: per item, team_item live + board_similar, then team_propose_card - Link to #n (with the matching call or line) or New card (kind from the type mapping) or Ignore.
  • Then the Inbox as today; a card that matches an open Azure bug gets a proposal to link it (team_link_card, consent).
/alfred-fix
fix cards
  • Reads the card's Azure items (team_card_items, team_item) - repro, acceptance, Azure comments - before the plan.
  • May propose "Also post to Azure" for its Did/Found comment; never moves the Azure state (that follows Verified).
/alfred-verify
verify fixes
  • For each card it marks ready, prepares the Tell Azure bundle: state move (per the item's process), evidence comment (call summary, card link), the re-test calls as a redacted .html - one consent card per Azure item.
  • A card whose Azure item was closed by someone else: reports it and proposes the card move instead.
/alfred-sync
catch up
  • Also catches up with Azure: team_refresh_item on the main and every card-linked item, reports each diff (state, text, comments, tree), proposes card moves for Azure closes/reopens and a brief update when the main's text changed.
/alfred-status
where things stand
  • Adds: Incoming from Azure (count, oldest), consent cards waiting on the user, Azure changes on the main and card items since the last look, and "on you" (team_search mine + board_search mine).
/alfred-live
board chat
  • Handles chat asks about Azure: "what's on me", "find the bugs in Payments", "update the bug on Azure with what you found" - reads live, writes only as one bundled consent card.
/alfred-listen and /alfred-review
check calls
  • A finding that matches an open Azure bug (team_search by endpoint, error text): propose linking the new card to it; a finding with no Azure item: propose Create in Azure only when the user asks for Azure tracking on this board.
/alfred-spec
brief and specs
  • Seeds or re-seeds Acceptance items from the main item; when the main's acceptance criteria change in Azure, shows before/after and waits.
/alfred-resume
pick up a task
  • Loads the board's main item (saved copy + diff), its tree as references, and the card links, and says what changed in Azure since the last session.
/alfred-report
summaries
  • Adds the Azure side per card (item, Azure state, what was sent) and can draft the report as a Tell Azure comment (consent).
/alfred-ask
questions from the board
  • May read Azure items live (references too) to answer; never writes to Azure from an ask.
/alfred-guide
teaching
  • Teaches the Team flow: token, search, Start, main item, Related items, Incoming, card links, Tell Azure, watch rules and the hook.
/alfred-team (new)
suggested new skill
  • One skill for the tracker side when no board task is running: search (mine, by filters, by text), add to a board / link to a card / start, sort Incoming across boards, sync all main and card items, prepare Tell Azure bundles, set up watch rules and the hook. Uses only team_* and board_* tools; every write is a consent card.
/alfred-connect, /alfred-update-skills
unchanged
  • Only the tool names they list change; the 17 skills ship and install as today (tests/python/test_alfred_skill.py checks every tool a skill names exists - skills change in the same change as the tools).
