Team search - saved searches and a loading skeleton

Mock for review. A search (text, every filter, Open only, Show) can be saved under a name; saved searches sit as pills above the results - one click runs it. Each pill's ⋯ edits it (the form fills, you change it, Save changes), renames, reorders or deletes it. While a search reads Azure, the table shows grey skeleton rows in its own shape. Click the pills, ⋯ and the buttons; the right panel switches states.

Decisions in this mock

WhatHow
What a saved search holdsThe whole search: text, every filter with its values and modes (sub-areas, tags any/all), Open only, sort, and Show (items / parents / tree). Not the page - it always opens on page 1.
Where it is keptIn Alfred (teamboards.db, per connection) - so it is there on every browser and machine, and Claude can run it (team_search saved: "My open bugs"). Everyone using this Alfred sees the same pills, like the rest of the Team tab.
Save☆ Save search next to Filters opens a small bar: name (required, unique per connection) → Save. The new pill is added at the end and lit.
RunClick a pill: the form fills with it, the search runs, the pill stays lit. Change anything in the form and the pill un-lights with a "changed" dot - the saved one is untouched until you save.
Edit⋯ → Edit: the form fills, the pill turns dashed amber, an "Editing" bar shows Save changes / Save as new… / Cancel. Change filters, run as often as you like, then save.
Rename, reorder, delete⋯ → Rename (inline), ← Move left / Move right →, Delete (asks once, says the name). No drag-and-drop on touch screens; the arrows work everywhere.
Count on the pillThe number of matches from the last time it ran (dim), so a pill says "7" before you click it. Not re-counted in the background (no polling).
Saved watch rulesUntouched - a watch rule is a search that runs on its own for a board; a saved search is a shortcut you click. A pill's ⋯ offers Watch on a board… to turn it into a rule.
LoadingFrom the click until Azure answers: the table keeps its header and shows 8 skeleton rows (grey bars sized like id, type, title, state pill, person pill, iteration, age); the sheen sweeps left to right, each row a little later. The count line says "Searching…". With "reduce motion" the bars stay still. A search under 150 ms never flashes the skeleton.
Paging and ShowNext/Prev and switching Show also show the skeleton; in tree mode the skeleton rows are indented in steps.
MCPteam_saved lists the saved searches; team_search takes saved: "name" (and any filter given beside it overrides that one). Claude does not create, change or delete them.
