0b · The fixes for that

  • One answerer per board, always: the listen runner's live lane and /alfred-live check the board's live-runner record for each other - also when a chat owns the cycle. The second one stays quiet and says "answered by the listen lane on LAPTOP-…". The backend refuses a second Claude reply to the same comment within 60 s (returns the first one), as a safety net.
  • No duplicate questions: board_ask on a card that already has an open Claude question with the same words returns that question instead of asking again.
  • A question has a state: open → answered (your reply), withdrawn (Claude, with a reason - e.g. "your answer to [688] covers it"), or snoozed (Decide later). Needs decision is derived: on while any question is open, off when none is. Claude can no longer clear the flag by hand while a question is open - it must withdraw the question, and you see why.
  • Open questions are never hidden: shown on the tile, the drawer and the dialog whatever the card's status or what else it waits on. A card can wait on a re-test and on you: both pills show.
  • Today's leftovers: [691] gets marked withdrawn ("same as [688], answered") when this ships; the double replies stay in history.

5 · What changes

  • One answerer per board (the cause of the duplicates) and no duplicate questions - see 0b.
  • Answers open questions: an option can carry a follow-up (options[].followUp) shown at once in the dialog and dropped if the answer changes; and after a Send, Claude may ask again - each new question names the answer it comes from (because, linked to that answer), arrives in the open dialog live (the board signal, no polling) and raises the count on the card. Claude never asks the same thing twice: an answered question is a decision it reads first.
  • Questions have a state (open / answered / withdrawn / snoozed); Needs decision follows them; open ones always counted on the card.
  • MCP board_ask: questions[] (1-4) with header, why, multiSelect, options (label, description, then, recommended, preview) and about; a plain question still works. board_withdraw_question (with a reason). Answers reach Claude as one JSON batch per send in board_wait, board_live, board_changes, board_get.
  • Frontend: the ❓ count on the tile, the drawer header and the nav; the dialog above (tabs, options with previews drawn by the board's own blocks, multi-select, Something else with the full editor, a note, Review, Send N answers; Decide later per question).
  • Skills (rules.md): ask with options - each says what Claude will then do, one Recommended, a preview when the choice changes something visible; several related questions in one ask; act only on the answered ones.
  • Tests: runner single-answerer, MCP schema and answer batch, backend states and flag, frontend tile / dialog / thread, export round-trip.
