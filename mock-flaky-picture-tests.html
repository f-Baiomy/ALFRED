Why the picture tests are flaky - and the fix

Two Karma specs, snippet-frame.spec.ts "draws a PNG of itself…" and snippet-shot.spec.ts "is opaque…", fail about 1 run in 3 when the whole board suite runs, and never alone. The same happens on the code before today's changes.

The frame element is always 300 × 120 and visible. Inside it, the page measured itself as 0 wide and 0 high, so it drew a 1 × 1 picture and never sent its height.

Cause

Before
1
The test adds the locked frame. Chrome runs a sandboxed frame in its own process.
2
The frame's page loads. At DOMContentLoaded it says ready at once.
3
Under load, the frame's own size has not arrived yet from the page's process: its window is 0 × 0.
4
The test asks for a picture right after ready. The page measures 0 × 0 and draws 1 × 1. Its height was 0, so no height was sent.
5
A moment later the size arrives and the page lays out, too late for the test.
After
1
Same frame, same page.
2
The page says ready only once its window has a size. If it is still 0 wide, it waits for the window's resize event (no timer, no polling).
3
Its height is sent first (the body was laid out), then ready.
4
A picture is also drawn only once the window has a size, so a ⬇ PNG or a kept picture can never be 1 × 1.
This is not only a test problem. The same race can give Alfred a 1 × 1 kept picture, or a 1 × 1 ⬇ PNG, when a snippet is opened on a busy machine. The board usually waits 1.5 s before keeping a picture, which hides it most of the time. The tests are not changed: they were right to fail.

The change (frame runtime, shared/utils/snippet-frame.ts)

// Before: ready at DOMContentLoaded, whatever the window's size
- function start(){fileRefs();loadDeclared();size();try{new ResizeObserver(size).observe(document.body)}catch(e){}if(!boot.holdReady)post({t:"ready"})}
- window.__alfredReady=function(){size();post({t:"ready"})};
- function shot(id,scale){settled().then(function(){draw(id,scale)})}

// After: a window with no size yet waits for its first resize - for ready, for Python's ready, and for a picture
+ function sized(f){if(window.innerWidth>0)return f();var h=function(){if(window.innerWidth>0){removeEventListener("resize",h);f()}};addEventListener("resize",h)}
+ function start(){fileRefs();loadDeclared();try{new ResizeObserver(size).observe(document.body)}catch(e){}
+   sized(function(){size();if(!boot.holdReady)post({t:"ready"})})}
+ window.__alfredReady=function(){sized(function(){size();post({t:"ready"})})};
+ function shot(id,scale){sized(function(){settled().then(function(){draw(id,scale)})})}

Plus one new spec: a frame whose window gets its size late still sends its height and then ready, and its picture is the full page. The test adds the frame with width:0, then sets it to 300 px after load. Today that test fails every time instead of 1 in 3.

How it will be checked

  • The new spec fails on the current code and passes with the change.
  • The full board suite (118 specs) 10 times in a row, with no failures. Before the change, 3 of 10 runs failed.
  • On card #39, live: the snippets still open, and ⬇ PNG gives the full page.
